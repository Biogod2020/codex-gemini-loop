# 用循环创建这个 skill：实际示例

日期：2026-10-17。

用户要求把科研图合作经验抽象成不限于 figure 的协作方式，并要求创建过程本身使用这个循环。原科研图入口和仓库地址保留，通用 skill 独立安装。

## 已完成的第一轮：共同设计 → 形成实际初稿

Codex 先提出角色分工、定向交接、事实裁决和停止条件，将设计简报交给 Gemini 共同设计。

请求模型：`gemini-3.8-flash-high`；服务返回标识：`gemini-3.8-flash-n`。

| Gemini 的意见 | Codex 的取舍与落地 |
| --- | --- |
| 原样作品与目标比作者自我辩护更有助于审阅 | 采纳：交接包含实际文本、图像或 diff，也保留判断必需的背景 |
| 允许在方向定型前参与构思 | 采纳：新增早期共同设计入口，不强制所有任务先开讨论 |
| 建议默认只审一轮 | 按实质问题与增益决定轮数，针对重要改动再复核 |
| 审美分支都呈交给用户 | 优先根据用户已知偏好解决，关键未知再聚焦提问 |
| Codex 唯一拥有操作权 | 明确 Codex 对实施和最终结果负责，工具分工按实际环境确定 |

Codex 随后写出通用入口、交接提示与仓库说明；图形工具由科研图专业入口承载。

## 第二轮：Gemini 直接阅读初稿 → 核实取舍 → 修订

Codex 提供了通用 skill 完整初稿、交接提示、仓库说明和上述第一轮记录。Gemini 阅读这些文本，为方法介绍改写、保留公共接口的代码实现、局部改稿三类情景提出执行建议。

| Gemini 的意见 | Codex 的取舍与落地 |
| --- | --- |
| 局部修改需要更明确的范围隔离 | 采纳：交接区分只读上下文和可改部分；应用替换后对照基线确认范围 |
| 风格摇摆时需要更明确的判断 | 保留原收敛规则，补充依据受众和已认可上下文作选择，关键未知再提问 |
| 调用失败时仍应展示已做成果 | 交付可用部分，标明调用状态，并按发布条件决定后续动作 |

这一轮继续请求 `gemini-3.8-flash-high`，返回标识为 `gemini-3.8-flash-n`。模型身份按实际元信息记录；最终判断和修改由 Codex 完成。

## 第三轮：修改后复核 → 独立检查 → 收敛

Codex 将修订后的完整入口、交接模板、实际示例与仓库说明再次交给 Gemini。请求模型为 `gemini-3.8-flash-high`，返回标识为 `gemini-3.8-flash-n`。

Gemini 报告影响本次交付的实质问题为 0，确认局部改动范围、风格收敛和调用失败边界已得到澄清。

Codex 完成了新旧 skill 的格式校验、相对引用检查、未完成脚手架检查和私人路径／服务端点检查，并核对调用元信息和文本情景。当前请求已满足、实质问题已解决，随后交付。
